# 0004 DB 커밋 후 Redis 초기화 실패를 허용한다

- 상태: 채택
- 적용 범위: stock의 신규 재고 생성
- 기록일: 2026-11-07

## 배경과 대안

DB를 최종 기준으로 지향하며 Redis는 조회와 주문 재고 차감 성능을 높이는 용도로 사용하려 한다.
Redis 장애 때문에 재고 생성 DB 저장까지 실패시키는 방식은 이번 요구와 맞지 않는다.
Redis 반영용 Outbox나 자동 복구 작업을 추가할 수도 있으나 현재 초기화에는 도입하지 않는다.

## 결정

재고와 처리 이력 및 생성 이벤트를 DB에 커밋한 뒤 신규 Stock인 경우에만 Redis 초기화를 시도한다.
`SET NX`로 기존 값을 덮어쓰지 않고 초기값 0을 추가한다. TTL은 설정하지 않는다.
Redis 접근 실패는 로그로 남기고 리스너는 정상 반환한다. Redis 실패만으로 Kafka 재시도나 DLT 이동을 하지 않는다.
중복 메시지나 기존 상품은 Redis 초기화를 다시 시도하지 않는다.

## 감수한 위험과 미정 사항

- DB 커밋과 Redis 쓰기 사이의 종료 또는 Redis 장애로 키가 누락될 수 있다. 이후 요청에서의 복구 기능은 아직 없다.
- `SET NX`는 기존 값 보존만 보장한다. 기존 값이 오래되었어도 보정하지 않고 TTL도 없어 불일치가 지속될 수 있다.
- 지연된 초기화와 향후 재고 변경이 겹치면 빈 키에 오래된 0을 기록할 수 있다. 초기화와 변경을 조정하는 정책이 필요하다.
- Redis가 DB 미반영 예약을 유일하게 보관하게 되면 DB 수량만으로 정확히 복구할 수 없다. 예약을 영속화할지와 미반영 차감 유실을 허용할지는 아직 정하지 않았다.
- Redis 호출은 DB 커밋 이후에도 동기로 수행하므로 타임아웃 동안 Kafka 소비가 지연될 수 있다.

현재 키와 타임아웃 및 코드 링크는 [재고 동작](../domains/stock.md)을 참조한다.
단순 DB 복사로 모든 재고 복구가 해결된다는 근거로 이 결정을 사용하지 않는다.

# 0010 DB 수량과 버전으로 Redis 반영과 대사를 수행한다

- 상태: 채택
- 적용 범위: stock의 증가·초기화·대사
- 기록일: 2026-11-08
- 이전 결정: [0004 초기화](0004-stock-redis-initialization.md)

## 배경과 결정

증가량을 Redis에 더하면 지연된 요청과 대사가 겹칠 때 중복 반영될 수 있다.
DB 행 락은 커밋 후 Redis 쓰기까지 보호하지 못하므로, 실행 순서 대신 버전으로 최신 상태를 선택한다.
커밋 후 확정된 전체 수량과 버전을 Hash에 전달하고 Lua로 비교·저장한다. 같은 버전의 수량 보정도 허용한다.
초기화는 키가 없을 때만 수행한다. 주기 대사는 같은 갱신 규칙으로 실패·누락과 문자열 키를 복구한다.

## 위험과 검증

DB와 Redis 사이의 즉시 일치는 보장하지 않으며 장애와 대사 소요 시간만큼 복구가 지연된다.
기존 INCRBY·문자열 쓰기 프로세스는 전환 전에 모두 중지해야 한다.
재고 감소와 예약에는 전체 수량 덮어쓰기를 그대로 적용할 수 없다.
역순·반복 반영, 큰 버전, 대사와 증가의 양방향 경합, 실패 후 복구를 실제 Redis와 PostgreSQL에서 검증한다.

# 0008 저장된 멱등성 키의 재고 증가 요청을 거절한다

- 상태: 대체됨 — [0009 공통 요청 이력](0009-stock-request-history.md)
- 적용 범위: stock 재고 증가 API
- 기록일: 2026-11-08
- 대체하는 결정: [0007 재고 증가 처리](0007-stock-increase.md)

## 배경과 대안

기존 구현은 같은 요청의 응답을 재사용하려고 요청 증가량, 결과 수량과 응답 완료 상태를 저장했다.
이번 요구에는 중복 증가를 막는 기능이면 충분하므로 요청 내용 비교와 응답 저장을 제거한다.
기존 응답을 재반환하는 대안은 채택하지 않는다. 중복 오류는 이미 처리한 키와의 충돌을 뜻하는 `409`로 정한다.

## 결정

- 요청 이력에는 멱등성 키와 상품 ID 및 생성 시각만 저장한다. 같은 키이면 요청 내용에 관계없이 거절한다.
- 키의 유일 제약, 재고 증가, Outbox 저장을 하나의 DB 트랜잭션으로 묶는다. 실패하면 키도 롤백된다.
- 해당 키의 유일 제약 예외만 API 예외 처리에서 `409 DUPLICATE_STOCK_INCREASE_REQUEST`로 변환한다.
- 커밋 후 Redis 증가를 한 번 시도하고 결과를 반환한다. 응답 저장을 위한 추가 DB 트랜잭션은 사용하지 않는다.
- 낙관적 락 충돌의 실패 처리, Redis 실패 허용, 기존 Outbox Relay의 Kafka 발행은 유지한다.

## 감수한 위험

최초 응답을 받지 못한 클라이언트는 재요청 시 중복 오류를 받으며 원래 결과를 재조회할 수 없다.
키가 존재한다는 사실은 DB 증가가 커밋됐다는 의미이고 Redis 성공이나 HTTP 응답 수신을 보장하지 않는다.
DB 커밋 후 Redis 미반영과 데이터 유실 복구, 대사는 이번 범위에 포함하지 않는다.
이력 삭제와 키 재사용은 중복 증가를 허용할 수 있으므로 보관·정리 정책은 별도로 정해야 한다.

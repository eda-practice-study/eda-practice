# 1주차 구조에서 발생할 수 있는 문제점

`상품 생성 → 이벤트 → 재고 생성` 구조와 `stock 이 product 를 호출하지 않는다`는 제약에서 나오는 문제들.

---

## A. 이벤트 전달 신뢰성

### A-1. 이벤트 유실

- **증상** 상품은 생성됐는데 재고 row 가 영영 생기지 않아 재고 등록이 계속 404
- **원인** DB 커밋 후 Kafka 전송이 실패하면 이벤트가 사라진다. `send()` 는 비동기라 API 는 이미 201 을 반환한 뒤다
- **대응** 현재는 `whenComplete` 로 ERROR 로그만 남긴다(유실을 막지 못하고 보이게만 함). → **Transactional Outbox**


### A-2. 중복 소비

- **증상** 같은 이벤트가 두 번 처리됨
- **원인** Kafka 는 at-least-once. 리스너가 처리 후 오프셋 커밋 전에 죽으면 재전달된다

### A-3. 컨슈머 무한 재시도

- **증상** 특정 메시지에서 막혀 뒤 메시지가 전부 밀림
- **원인** 처리 실패 시 오프셋이 진행되지 않아 같은 메시지를 계속 재시도한다

---

## B. 일관성

### B-1. 최종적 일관성 지연

- **증상** 상품 생성 직후 재고를 등록하면 404. 정상 동작인데 사용자에겐 버그로 보인다
- **원인** 이벤트 전파가 비동기다.
- **대응** 재고 준비 상태 조회 API 나 어드민 UI 의 폴링이 필요

### B-2. Stock 생성 실패에 대한 보상이 없다

- **증상** Product 는 생성됐는데 Stock 생성이 계속 실패해도 되돌리는 장치가 없다

---

## C. 동시성

### C-1. 재고 등록의 Lost Update

- **증상** 동시에 두 요청이 오면 한쪽 증가분이 사라질 수 있다
- **원인** `조회 → 수량 변경 → 커밋` 이 read-modify-write 라 두 트랜잭션이 같은 초기값을 읽는다
- **대응** 없음 → **락 / 원자 UPDATE**

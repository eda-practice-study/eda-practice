# 개발 설계와 인수인계

이 폴더는 개발 과정에서 합의한 설계와 현재 구현 상태를 관리한다.
`docs/`는 스터디장이 관리하는 명세와 참고 자료로 두고 수정하지 않는다.
이 문서의 구현 상태는 2026-11-08에 확인한 소스 기준이다. 이후 변경 시 관련 문서를 함께 갱신한다.

## 다음 세션에서 읽는 순서

1. [개발 작업 합의](../AGENTS.md)를 읽고 `git status --short`로 작업 트리의 기존 변경을 확인한다.
2. 아래 구현 현황과 [전체 이벤트 흐름](architecture/events.md)을 확인한다.
3. 작업할 도메인의 동작 설명과 연결된 결정 기록을 읽는다.
4. 실행이나 재현이 필요하면 [실행과 확인 절차](runbook.md)를 사용한다.

## 현재 구현 상태

| 범위 | 구현된 내용 | 아직 구현하지 않은 내용 |
|---|---|---|
| product | `POST /api/products`, 상품과 Outbox 저장, 상품명 중복 처리 | 상품 목록 조회와 stock 연동 |
| stock | 상품 생성 이벤트 소비, 초기 재고 0, Redis 초기화, 멱등성 키를 사용하는 재고 증가 API, `StockCreated`와 `StockIncreased` 발행 | 재고 조회 API, 대사와 캐시 복구, 주문 재고 차감과 예약 복원 |
| order | 상품 생성 이벤트 소비, 상품 스냅샷과 처리 이력 저장, `ProductSnapshotCreated` 발행 | 주문 API와 Saga, 상품 수정 이벤트에 따른 스냅샷 갱신 |
| 공통 | OutboxRelay, 메시지 규격, stock과 order의 BATCH ACK 및 재시도와 DLT | DLT 조회와 재처리 API, 이력과 Outbox 정리 정책 |
| notification | `*.events`를 별도 그룹으로 소비해 로그 출력 | 실제 알림 발송과 그에 대한 멱등 처리 |

엔티티에 일부 주문 동작이 존재하는 것과 주문 API나 Saga가 완성된 것은 구분한다.
[기존 API 명세](../docs/api/README.md)는 목표 계약도 포함하므로 구현 완료 목록으로 해석하지 않는다.
결제와 관측 도구 등 [프로젝트 소개](../README.md)의 학습 목표도 이 표의 구현 완료 범위를 확대하지 않는다.

## 갱신 원칙

- 도메인 문서는 현재 동작을 설명하고, 결정 기록은 선택 이유와 위험을 설명한다. 같은 내용을 여러 곳에 복사하지 않고 링크로 연결한다.
- 이벤트 필드와 공통 Kafka 정책은 `architecture/events.md`를 기준으로 관리한다.
- 설계를 변경하면 도메인 문서와 구현 상태를 갱신하고, 중요한 결정 변경은 [결정 기록 관리 규칙](adr/README.md)을 따른다.
- 세션 대화나 커밋 목록을 계속 쌓는 일지는 만들지 않는다. 일시적인 미커밋 상태는 다음 세션에서 Git으로 확인한다.
- 아직 정하지 않은 사항은 결정된 것으로 쓰지 않는다. 특히 Redis 예약 수량의 복원과 DLT 재처리 방식은 미정이다.

# 0005 상품 생성 이벤트로 기존 스냅샷을 갱신하지 않는다

- 상태: 채택
- 적용 범위: order의 상품 스냅샷 생성
- 기록일: 2026-11-07

## 배경과 대안

동일 상품의 생성 이벤트가 중복되거나 새로운 메시지 ID로 다시 전달될 수 있다.
마지막으로 받은 값으로 덮어쓰면 과거 이벤트가 현재 이름과 가격을 되돌릴 수 있다.
기존 값과 다른 경우 오류로 분류하는 대안도 검토했으나 생성 처리에서는 기존 값을 보존하기로 합의했다.

## 결정

상품 ID의 스냅샷이 없을 때만 만들고 `ProductSnapshotCreated`를 기록한다.
이미 스냅샷이 있으면 이름과 가격을 변경하지 않고 새 입력 메시지의 처리 이력만 저장한다.
같은 messageId면 이력도 추가하지 않는다. 발행 이벤트에는 상품 ID와 이름 및 가격을 담는다.

## 감수한 위험

서로 다른 생성 메시지의 내용이 달라도 이를 업무 오류로 보고하지 않는다.
이 정책만으로 최신 상품 정보를 유지할 수는 없다. 상품 수정 이벤트, 버전과 갱신 순서는 별도 설계가 필요하다.
스냅샷 생성 사실은 재고나 Redis의 준비 완료를 보장하지 않는다.

구현과 검증 링크는 [order 도메인 문서](../domains/order.md)를 참조한다.

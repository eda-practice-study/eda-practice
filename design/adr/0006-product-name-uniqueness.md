# 0006 사전 조회와 DB 유일 제약으로 상품명 중복을 처리한다

- 상태: 채택
- 적용 범위: product의 상품 등록
- 기록일: 2026-11-07

## 배경과 대안

상품명 중복은 409로 응답해야 한다. 사전 조회만으로는 동시 요청의 중복을 막을 수 없다.
DB 예외만으로 처리할 수 있지만 서비스가 Hibernate 예외의 원인과 제약 이름을 직접 해석하면 업무 흐름을 읽기 어렵다.
저장 어댑터를 도입하는 대안도 있으나 현재 규모에서는 추가 계층 없이 처리한다.

## 결정

서비스는 `existsByName()`으로 중복을 확인하고 업무 예외를 던진다.
DB는 이름을 지정한 `uk_product_name` 유일 제약으로 최종 중복을 막는다.
상품 전용 `ProductControllerAdvice`가 해당 제약 위반을 409로 변환한다. 다른 무결성 오류는 500으로 처리한다.
DB 제약 이름은 엔티티의 공개 상수로 노출하지 않고 매핑과 예외 변환 영역에서 다룬다.

## 감수한 위험

사전 조회가 추가되고, 동시 요청 중 일부는 DB 예외 경로로 처리된다.
예외 처리기는 Hibernate의 예외 구조와 제약 이름에 의존한다. DB 스키마나 매핑 변경 시 함께 검토해야 한다.
모든 무결성 위반을 상품명 중복으로 처리하면 실제 오류를 숨기므로 해당 제약만 식별한다.
이 선택은 HTTP 요청 멱등성을 구현한 것이 아니다.

구현과 API 설명은 [상품 도메인 문서](../domains/product.md)를 참조한다.

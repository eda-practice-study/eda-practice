# 0007 멱등성 키로 DB 재고 증가를 확정하고 Redis 실패를 허용한다

- 상태: 대체됨 — [0008 중복 요청 거절](0008-stock-increase-duplicate-rejection.md)에서 멱등성 정책을 단순화했다.
- 적용 범위: stock 재고 증가 API
- 기록일: 2026-11-08

## 배경과 대안

재고 증가는 빈도가 높지 않고 DB 변경의 확정이 우선이다. Redis나 Kafka 장애가 DB 증가를 취소해서는 안 된다.
HTTP 재전송은 같은 증가분을 다시 반영하지 않아야 한다.

Redis를 DB 트랜잭션 안에서 증가시키면 이후 DB 커밋 실패 시 Redis 증가를 되돌릴 수 없다.
증가 작업을 영속화하고 Redis에서 작업 ID로 중복을 확인하며 재처리하는 대안도 검토했지만,
이번에는 Redis 증가 재시도와 유실 복구를 구현하지 않기로 했다.
Redis에 DB 수량과 버전을 덮어쓰는 방식이나 대사도 이번 구현에는 포함하지 않는다.
예약이 도입되면 실재고와 가용 재고가 달라진다는 점은 후속 설계에서 다룬다.

## 결정

- 재고의 낙관적 락으로 동시 수정 충돌을 감지한다. 충돌은 실패로 반환하며 자동 재시도하지 않는다.
- 재고 증가, HTTP 멱등성 이력, `StockIncreased` Outbox를 같은 DB 트랜잭션으로 커밋한다.
- 별도의 서비스 빈에서 DB 커밋 후 Redis 증가를 한 번 시도하고, 실패나 결과 불확실 시 가용 재고를 `null`로 반환한다.
- 멱등성 키는 API 전체에서 유일하며, 같은 키의 다른 요청은 거절한다. 완료 요청은 최초 응답을 반환한다.
- Redis 처리 전 이미 DB에 요청 이력이 남는다. 응답 완료를 기록하지 못한 키는 미완료 오류로 구분하고 재실행하지 않는다.
- Redis 명령의 재연결 재전송을 제한하며, Kafka는 기존 Outbox Relay가 독립적으로 재시도한다.

## 감수한 위험

DB 커밋과 Redis 반영 및 응답 완료 기록은 하나의 원자적 작업이 아니다.
프로세스 종료나 Redis 장애로 두 저장소가 불일치할 수 있으며 현재 자동 복구하지 않는다.
응답 완료 기록에 실패하면 최초 요청이 성공을 반환해도 재전송은 미완료 오류가 될 수 있다.
미완료는 Redis 미반영을 뜻하지 않으므로 해당 키로 증가를 재실행하거나 이력을 임의로 삭제하지 않는다.
멱등성 이력의 보관 기간과 미완료 이력의 운영 복구 절차는 후속 과제다.

## 관리 규칙

- 하나의 파일은 하나의 중요한 결정을 다룬다. 구조, 인터페이스, 장애 처리나 정합성에 영향을 주는 선택을 기록한다.
- 번호는 저장소 전체에서 순서대로 부여하고 재사용하지 않는다. 적용 도메인은 본문과 이 목록에 표시한다.
- 각 기록은 상태와 적용 범위, 배경, 고려한 대안, 결정, 감수한 위험, 관련 구현 또는 문서 링크를 담는다.
- 아직 합의하지 않은 내용은 `검토 중`으로 기록한다. 합의한 내용은 `채택`, 다른 결정이 대체하면 `대체됨`으로 표시한다.
- 결정이 바뀌면 새 기록을 추가하고 이전 기록에 대체 문서의 링크를 남긴다. 이전 이유를 삭제하지 않는다.
- 오탈자나 잘못된 사실은 수정할 수 있다. 현재 동작 설명은 도메인 문서에서 갱신하고 결정 본문에 복제하지 않는다.
- 상태가 `채택`이라는 것이 모든 운영 위험을 해결했다는 뜻은 아니다. 남은 위험과 미정 사항도 함께 읽는다.
- 임시 작업 트리 상태와 세션별 진행 일지는 기록하지 않는다. 단순한 클래스 이름 변경마다 결정 기록을 만들지 않는다.

기록 방식 참고: [Michael Nygard의 설계 결정 기록 제안](https://www.cognitect.com/blog/2011/11/15/documenting-architecture-decisions).
